# SOP：游戏舆情与槽点分析平台

> 本文档是项目的施工总纲，记录**最终方案**与**实测依据**。
> 所有结论都经过真实请求验证，未验证的会明确标注。

## 1. 项目定位

**回答的唯一核心问题：玩家对某款头部游戏的情绪如何？主要在骂什么？**

围绕一个问题做深，不做大而全的舆情平台。

- 输出一：纵览页 —— 各游戏情绪分横向对比 + 槽点 Top3
- 输出二：单游戏详情页 —— 日声量趋势、槽点分布、每类槽点原声、最受认可的差评/好评

## 3. 数据源决策

### 3.1 最终选择

| 源 | 覆盖游戏 | 语言 | 凭据 | 角色 |
|---|---|---|---|---|
| **Steam** | 终末地、鸣潮、绝区零、三角洲行动、恶意不息 | 中文 | 无需 | 主力源 |
| Reddit | 原神、崩坏：星穹铁道、明日方舟 | 英文 | OAuth client_id + secret | 补位源 |

### 3.2 为什么主力是 Steam

1. **官方公开接口，无需凭据，不受出口 IP 风控影响**——在出口 IP 被风控限制的网络环境下实测仍可用，这一点在中文源里是独一份
2. `language=schinese` 支持按语言筛选，直接拿到**中文玩家评测**，语言诉求没有被牺牲
3. `voted_up` 字段是 Steam 官方标注的好评/差评，**情绪极性不需要做情感分析**，省掉整层模型
4. 附带高质量辅助字段：

| 字段 | 用途 |
|---|---|
| `timestamp_created` | 时间窗过滤的唯一可靠来源 |
| `votes_up` | 评论认可度，用于挑选「共识性槽点」 |
| `playtime_at_review` | 游玩时长，可识别「没玩过就喷」 |
| `language` | 语言筛选依据 |
| `author.steamid` | 写入前即哈希假名化（见 7.8） |

### 3.3 被排除的源及实测依据

**B 站 —— 仅评论接口可用，无法自动发现内容**

| 接口 | 用途 | 实测结果 |
|---|---|---|
| `x/web-interface/view` | 视频详情 | ✅ 可用 |
| `x/v2/reply/wbi/main` | 抓评论 | ✅ 可用，能拿到真实评论 |
| `x/web-interface/newlist` | 分区最新投稿 | ⚠️ 仅顶级 `rid=4`；分页返回重复数据；500 条里仅 20 条有评论 |
| `x/web-interface/wbi/search/type` | 关键词搜视频 | ❌ `code=0` + `v_voucher` 风控空响应 |
| `x/web-interface/popular`、`ranking/v2` | 热门/排行 | ❌ `-352 风控校验失败` |
| `x/space/wbi/arc/search` | UP 主投稿 | ❌ `-352 风控校验失败` |

判断依据：搜索接口**带签名与不带签名返回完全一致**，说明卡点不是 WBI 签名，而是浏览器指纹（`w_webid` / `buvid_fp`）。解开它需要伪造浏览器指纹，属于绕过反爬，**本项目不做**。

配套产出：`src/collect/bili_client.py` 保留了可用的 WBI 签名、限速、重试、匿名指纹领取实现，若将来改为人工喂入 BV 号，可直接复用。

**NGA —— 内容按设计锁在登录之后**

| 探测项 | 结果 |
|---|---|
| `robots.txt` | PHPWind 默认规则，未禁内容页 |
| 首页 / `read.php`（两个域名） | `403`「访客不能直接访问」 |
| `app_api.php` | `{"code":4,"msg":"参数错误"}` / `{"code":2,"msg":"未定义服务"}` |

要抓需真实账号 `ngaPassportCid` + 逆向 App 签名。版规禁止爬虫，且把登录 Cookie 放进公开仓库等于泄露账号。**排除。**

**贴吧 —— 未做结论**

`robots.txt` 未禁 `/f?kw=` 与 `/p/`，但**禁了 `/f/search`**，即搜索路径不可用。贴吧的优势是每款游戏都有对应的吧（无需搜索），但全部请求都被 `403 百度安全验证` 拦下，**无法在当前网络下验证**。若将来换网络，这是值得回头试的路线。

## 4. 数据流与架构

```
config/games.yaml  ── 游戏名单 + 数据源 + appid
        │
        ▼  collect（唯一需要联网的环节）
data/raw/{slug}.json        {"stop_reason": ..., "reviews": [...]}
        │
        ▼  clean      去重 / 剔除广告与噪音
        ▼  tag        槽点关键词打标 + 情绪极性（取 voted_up）
        ▼  aggregate  按游戏聚合
data/public/overview.json
data/public/games/{slug}.json
        │
        ▼  fetch()
site/index.html + site/game.html
```

**分层原则**

- `collect` 是唯一联网环节。`data/public` 生成后，分析与前端完全离线可跑
- `data/raw` 是原始证据，永不手工修改，且**不入库**（合规：不二次分发原始数据）
- 删除 `data/public` 重跑 `--analyze-only` 应得到等价结果

## 7. 关键技术要点（含已踩过的坑）

### 7.1 时间窗必须本地过滤

**Steam 接口的 `day_range` 参数实测不生效。** 未传 / 1 天 / 7 天 / 30 天 / 365 天，`total_reviews` 返回值完全一致。

做法：用 `filter=recent`（按时间倒序）翻页，本地按 `timestamp_created` 判断是否越界，越界即停止翻页。

### 7.2 抓取上限会造成「假 0」

命中 `max_comments_per_game` 上限时，时间窗**早期日期**会显示 0 条——那是**没抓到**，不是当天没有评测。

产物中通过 `fetch_stop_reason`（`window_edge` / `cap` / `exhausted`）与概览里的 `capped` 字段标记，前端会显式提示。**这类偏差不标注出来，页面就是在骗人。**

消除方法：调大 `max_comments_per_game`，或改为按日分桶抓取。

### 7.3 情绪极性不做推断

直接取 `voted_up`。规则层只负责槽点打标，不负责判断情绪。这样规则层的错误不会污染情绪结论。

### 7.4 槽点打标是「减法」而非「穷举」

关键词规则表命中率实测 20%~50%。大量短评不含规则词，这是**预期内的**：

- 规则层负责**可解释、可复现**的基线
- 漏掉的部分交给 LLM 精修（未实现）

一条评论可命中多个类别，类别权重用于排行（如「氪金/卡池」权重 1.2 高于「剧情/角色」0.9）。

### 7.5 分类关键词要防类型陷阱

`taxonomy.yaml` 里的关键词 `648` 会被 YAML 解析成 **整数**，直接送进正则编译会抛 `TypeError`。规则加载时统一做 `str()` 转换。

### 7.6 Windows 缺时区库

`zoneinfo` 在 Windows 上需要 `tzdata` 包，否则 `Asia/Shanghai` 直接抛 `ZoneInfoNotFoundError`。已写入 `requirements.txt`。

### 7.7 清洗层处理真实噪音

实测遇到并已过滤的两类：

- **游戏内系统提示被贴进评测**：玩家会把启动时的反作弊/环境检测弹窗原文整段贴进评测，这类文本不含玩家观点，却会命中「外挂」类关键词
- **加群广告**：评论里夹带 Q 群号或私域联系方式招人（B 站与 Steam 两侧都出现，属跨源共性）

### 7.8 作者身份处理：假名化，不是匿名化

Steam `author.steamid` 在 `steam_client._normalize` 里就换成哈希（`sha256(salt + ":" + steamid)[:12]`），原始 ID **不写入 `data/raw`**。

**必须说清楚：这是假名化，不是匿名化。** 当前实现用的是写死在代码里的公开盐，而 steamid 是可枚举的空间，所以对已知 ID 可以反查；同一作者的哈希又稳定，跨游戏、跨快照可关联。

对 Steam 公开评测而言危害有限（内容本来就是公开的），但如果把本项目改用于**非公开 UGC**，这层哈希不构成任何保护。要真正降低关联性，盐必须每次部署随机生成且不入库。

## 9. 风险与应对

| 风险 | 现状 | 应对 |
|---|---|---|
| 出口 IP 被风控 | 已实测：在受限出口 IP 下 B 站 `popular`/`ranking` 返回 `-352`、百度弹安全验证、首页被降级 | 主力源选官方 API，不受此影响 |
| Steam 接口变更 | 未发生 | 客户端集中在一处，失败快速定位 |
| 抓取上限造成早期日期不完整 | 已发生（三角洲行动） | 产物标记 + 页面提示 + 可调上限 |
| 槽点漏检 | 已发生，命中率 20%~50% | 规则层保底，LLM 精修待接入 |
| 新游戏样本过少 | 已发生（终末地仅 12 条） | 样本量低于阈值时页面应弱化结论，当前仅靠人读 |
| z-score 拐点误报 | 样本稀疏时不可靠 | 少于 5 天直接不检测 |
| 中文评测的玩家群体偏差 | 存在 | Steam 中文评测以 PC 玩家为主，与手游/主机群体有差异，结论需注明 |
| 页面数据滞后 | 存在 | 页面顶部固定展示数据快照时间 |
