# 从零搭一个游戏舆情收集小工具

> 这是我学 AI 产品运营过程中做的一个小项目，边查边做。
> 代码很粗糙，但链路是通的：**抓公开评测 → 分析情绪和槽点 → 生成一个静态页面**。

## 我想做什么

起因很简单：我想知道玩家到底在骂什么。

看评分不够，评分只是一个数字。我想看**情绪**和**槽点**——最近在骂哪个系统、哪次活动、哪波数值，骂得凶不凶、是不是集中。

所以给自己定了三条：
- 只回答「玩家情绪怎么样、主要在骂什么」这一件事，别的都不做
- 数据必须来自公开渠道，不碰任何内部数据
- 产出一个静态页面就够，不搞后端

## 第一步就卡住了：数据源

这是我花时间最多的地方，也是整个项目最值得记的一段。

### 一开始想做 B 站

理由很直接：中文社区的情绪最真实。结果撞墙。

B 站的**评论**接口是能用的，但**搜索**接口不行：

| 接口 | 结果 |
|---|---|
| 视频详情 | 能用 |
| 评论 | 能用，能拿到真实评论 |
| 关键词搜视频 | `code=0`，但 `data` 里只有一个 `v_voucher` |

`v_voucher` 是风控空响应。我又分别试了「带签名」和「不带签名」，返回**完全一样**——说明卡点不是签名（我的 WBI 签名算法是对的，算出来的 `mixin_key` 和公开文档一字不差），而是 B 站另加的浏览器指纹校验。

要解开它就得伪造浏览器指纹。**我不想做这件事**，所以 B 站这条路我只留下了评论部分的代码。

### NGA 也不行

首页直接 403，页面标题写着「访客不能直接访问」，两个域名都一样。`app_api` 接口能通，但需要真实账号登录态 + 逆向 App 签名——内容被锁在登录之后，绕不开。放弃。

### 贴吧没结论

`robots.txt` 里禁了 `/f/search`，所以搜索这条路本来就不合规。但我连吧首页都打不开，所有请求都被「百度安全验证」拦下，测不下去，就搁置了。

### 最后选了 Steam

Steam 是我试下来唯一顺的：

- 官方公开接口，不需要任何凭据
- `language=schinese` 能筛中文评测，中文语境的诉求没丢
- **`voted_up` 字段直接告诉我这条是好评还是差评**——情绪极性不用做情感分析，省掉一整层

最后一条是本项目最大的运气。情绪判断本来是最难的一块，结果官方已经帮我标好了。

## 最后做出来的东西

抓 5 款游戏、近 30 天、970 条中文评测，得到这些：

| 游戏 | 有效评测 | 好评率 | 情绪分 | 最集中的槽点 |
|---|---|---|---|---|
| 三角洲行动 | 738 | 32% | **-0.35** | BUG与性能、运营、外挂 |
| 恶意不息 | 157 | 42% | -0.17 | BUG与性能 |
| 鸣潮 | 44 | 43% | -0.14 | 剧情与角色、氪金与卡池 |
| 绝区零 | 19 | 68% | +0.37 | 剧情与角色 |
| 终末地 | 12 | 92% | +0.78 | 氪金与卡池 |

情绪分 = `好评率 × 2 - 1`，范围 -1 到 1。终末地只有 12 条样本，那个 +0.78 没有统计意义，看看就好。

页面分两层：
- **纵览页**：各游戏情绪分横向对比 + 槽点 Top3
- **单游戏详情页**：日声量趋势、槽点分布、每类槽点的代表评论原声

## 目录结构

```
config/     配置：游戏名单、槽点分类、运行参数
src/collect/    数据源客户端（Steam 在用，B 站留作备用）
src/analyze/    清洗、打标、聚合
src/pipeline.py 总入口
data/demo/      合成演示数据（入库）
data/public/    真实产物（不入库）
site/           静态页面
docs/SOP.md     完整施工方案和实测结论
```

## 怎么跑起来

```bash
pip install -r requirements.txt

python src/pipeline.py --check-config   # 先看配置对不对
python src/pipeline.py --run            # 抓取 + 分析，需要能访问 store.steampowered.com

python -m http.server 8765 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:8765/site/index.html
```

想让页面显示真实数据，跑一次 `--run` 就行，结果写到 `data/public/`。

**什么都不跑也能看**：仓库里自带 `data/demo/` 合成数据，页面读不到真实产物时会自动回退到它。所以你 clone 下来直接起服务就能看到效果。

两个注意点：
- 页面必须用 http 服务打开，直接双击 html 文件读不到数据
- `data/public/` 和 `data/raw/` 都不入库——因为里面是真实玩家评测原文

## 我踩过的坑

按踩到的顺序：

**1. Steam 的 `day_range` 参数是假的。**
我本来以为传 `day_range=30` 就能拿到近 30 天。结果未传、1 天、7 天、30 天、365 天，返回的 `total_reviews` **一模一样**。时间窗只能自己在本地按 `timestamp_created` 过滤。

**2. 抓取条数上限会造出「假 0」。**
三角洲行动撞到 1000 条上限，页面早期日期的显示是 0 条。但那是**没抓到**，不是当天没人评测。这种偏差不标注出来，页面就是在骗人——所以产物里加了 `fetch_stop_reason`，页面也会提示。

**3. YAML 把 `648` 变成了整数。**
我的槽点关键词表里有个 `648`（手游充值档位），YAML 把它解析成 int，直接送进正则就抛异常。加载时统一转字符串才行。

**4. Windows 上没有时区库。**
`zoneinfo` 用 `Asia/Shanghai` 直接报错，要额外装 `tzdata`。

**5. 评论里混着不少垃圾。**
真实遇到两类：一是玩家把游戏启动时的反作弊弹窗**整段**贴进评测（这条会命中「外挂」关键词，但根本不是玩家观点）；二是加群广告，B 站和 Steam 两侧都有。

**6. 哈希不等于匿名。**
我一开始把作者 ID 的哈希写成「匿名化」，后来才发现不对：盐写死在代码里，而 Steam ID 是可枚举的，对已知 ID 可以反查。这只能叫**假名化**。要真正降低关联性，盐得每次部署随机生成。代码里已经改成可以从 `AUTHOR_SALT` 环境变量读。

## 现在还不够好的地方

- **槽点靠关键词规则，命中率只有 20%~50%。** 大量短评说不清具体槽点。这是规则层的天花板，得靠大模型精修来补
- **三角洲行动数据不完整**，撞了抓取上限，早期日期偏空
- **新游戏样本太少**，终末地只有 12 条，结论不能当真
- **只有 PC 玩家的声音。** Steam 中文评测以 PC 玩家为主，跟手游群体有偏差
- **`data/demo/` 是我手写的**，只为了让人看到页面效果，里面那几个占比数字不严谨，别当真实统计看
